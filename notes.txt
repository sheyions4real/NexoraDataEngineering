version = "0.1.0"

    "pyarrow>=18.0",
    "azure-identity>=1.19",

[project.optional-dependencies]

    "pytest>=8.0",

[tool.pytest.ini_options]

[tool.ruff]
line-length = 100

[tool.ruff.lint]

[tool.ruff.format]
quote-style = "double"

A few important choices:
- SQLAlchemy gives us a database abstraction rather than scattering SQL Server connection logic throughout the application.
- PyArrow will handle Parquet files.
- Azure Identity and the Data Lake SDK will handle authentication and storage operations.
- Pydantic Settings will centralize configuration.
- Pytest and Ruff establish our testing and code-quality standards.

1. What we are going to validate
For our first table, Sales.SalesOrders, we'll validate four things:
Validation	            What we want to establish
- File integrity	    The uploaded Parquet file can be downloaded and read
- Schema validation	    Expected source and ingestion columns exist
- Record count	        Number of records in Parquet matches SQL Server
- Data integrity	    Source records and destination records contain matching values

We'll eventually add null checks, duplicate detection, business rules and audit records. For now, let's establish the foundation.

2. How the pipeline will execute
For each table, the pipeline will perform this lifecycle:
1. Initialize ingestion run
   
   Generate a unique run_id, timestamp and load date. Create the initial IngestionAudit with RUNNING status.
2. Prepare Bronze destination
   
   Construct the partitioned destination using the supplied table metadata.
3. Extract source batches
   
   Call TableExtractionService.extract_table() using the supplied table and configured batch size.
4. Enrich and serialize
   
   Add ingestion metadata to each record and serialize the batch through DataSerializer.
5. Upload to ADLS
   
   Persist each Parquet file using the DataLakeStorage port.
6. Verify and validate
   
   Download the uploaded file, verify byte integrity, and validate its Parquet structure, row count, columns and keys.
7. Update audit metrics
   
   Update row, batch, file and byte counts, persisting the audit after successful batch processing.
8. Finalize execution
   
   Mark the audit SUCCEEDED and validation PASSED, or record the failure and preserve the error information.
